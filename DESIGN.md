# Design system

Editorial and typography-first. The reading column is the product; everything else
gets out of its way. No decorative animation, no carousels, no parallax.

All values live in [`src/styles/tokens.css`](src/styles/tokens.css). Nothing else in
the codebase is allowed to contain a raw colour, size or spacing value — if you need
one that does not exist, add a token.

---

## Colour

Two independent axes: **mode** (`data-mode`) and **accent** (`data-accent`), both on
`<html>`, both persisted in `localStorage`, both applied before first paint by one
inline script in `Head.astro`.

Every accent ships a light-mode and a dark-mode variant. The mode blocks in
`tokens.css` choose which half of each pair is live, so the two axes never interfere.

### Accents — every pair that ships

`/bg` is the link colour on the page background. `pill-txt / fill` is the pill text on
its tinted fill — a deliberately darker shade than the link colour, because the same
accent on a tint would not clear AA. `on-fill` is the text on a solid accent button.

Adding an accent means adding a ramp to `tokens.css`, an entry to `ACCENTS` in
`config.ts`, and re-running the check. Do not ship an unmeasured pair.

## Type

Two families, self-hosted in `/public/fonts` as latin-subset variable woff2 with
`font-display: swap`. Same-origin, no third-party font request, nothing render-blocking.

| Role | Family | File | Axis | Preloaded |
|---|---|---|---|---|
| Headings, post body | **Source Serif 4** | `source-serif-4-var.woff2` — 50 KB | `wght 400..700` | yes |
| Emphasis in prose | Source Serif 4 Italic | `source-serif-4-var-italic.woff2` — 50 KB | `wght 400..600` | **no** |
| UI, nav, meta, TOC | **Inter** | `inter-var.woff2` — 47 KB | `wght 400..700` | yes |

Two decisions worth keeping:

- **Weight-only axes.** Source Serif 4 also ships an optical-size axis; including it
  costs 119 KB per face instead of 50 KB. Dropping `opsz` and trimming the weight span
  to the range the tokens actually use halved the font payload — 294 KB → 147 KB — with
  no visible difference at these sizes. The `@font-face` weight ranges are declared to
  match the files exactly, so nothing is clamped or synthesised.
- **The italic is not preloaded.** It appears only in emphasis and blockquotes, and
  must not compete with the LCP element for bandwidth.

### Scale

Modular, ratio **1.25**, anchored on the 19px reading size. The top three steps are
fluid so a 360px screen never gets a headline that wraps badly.

| Token | Size | Use |
|---|---|---|

| `--step--1` | 0.95rem / 15px | meta, byline, captions, UI |
| `--step-0` | **1.1875rem / 19px** | **post body** |
| `--step-1` | 1.484rem / 24px | lead paragraph, h4, card titles |
| `--step-2` | 1.856rem / 30px | h3 |
| `--step-3` | `clamp(2rem, 1.6rem + 1.8vw, 2.32rem)` | h2 |

### Rhythm

| Token | Value | Applies to |
|---|---|---|
| `--leading-body` | 1.7 | post body |
| `--leading-heading` | 1.25 | h2–h4 |
| `--leading-display` | 1.15 | h1, hero |
| `--leading-ui` | 1.5 | nav, meta |
| `--paragraph-gap` | 1.35em | space between blocks in `.prose` |

Headings get `margin-top: 2em` (h2) and `1.6em` (h3) but only `0.6em` beneath, so a
heading binds visually to the text it introduces rather than floating between sections.

## Breakpoints

Mobile-first; every query is `min-width`. The base case is 360px.

| Width | What changes |
|---|---|
| base | single column, TOC above the article, cards stacked |
| 560px | signup form goes horizontal |
| 640px | category grid → 2 columns |
| 700px | post list and cards → 2 columns |
| 768px | inline ad reservation 300px → 280px; sidebar 280px → 600px |
| 900px | landing lead story goes horizontal, feature grid → 3 columns |
| 1000px | category grid → 4 columns |
| 1100px | **TOC becomes a sticky left rail**; post list → 3 columns |
| 1400px | **ad rail appears as a third column**, sticky |

The TOC is sticky only from 1100px, as specified — on mobile it is a static block
above the article, which needs no JavaScript and cannot shift the layout.

## Ad slots

Three positions, all rendered by [`AdSlot.astro`](src/components/AdSlot.astro):

| id | Placement | Where |
|---|---|---|
| `after-first-section` | inline | after the first `##` section |
| `mid-article` | inline | at the middle `##` boundary |
| `post-sidebar` | sidebar | right rail ≥1400px, end of article below that |

The inline positions are real section boundaries, not approximations: the rendered
HTML is sliced at `<h2>` offsets by
[`split-content.ts`](src/lib/split-content.ts), so an ad never lands mid-sentence.

| Token | Value |
|---|---|
| `--ad-h-inline` | 300px mobile → 280px ≥768px |
| `--ad-h-sidebar` | 280px mobile → 600px ≥768px |
| `--ad-w-sidebar` | 300px |

### Why zero CLS actually holds

The reservation is unconditional — the height comes from CSS and applies whether or
not `PUBLIC_ADS_ENABLED` is set. Enabling ads fills space that was already occupied.

Height alone is not sufficient, though. A creative *wider* than its column widens the
page and reflows every paragraph, which is a layout shift even when the reserved
height was correct — a 336×280 unit inside a 312px column on a 360px screen does
exactly this. `.ad-slot` therefore also carries `max-width: 100%` and
`overflow: hidden`, and constrains any injected `iframe`, `img` or `ins`.

Measured across six scenarios — 360/768/1440px, each with a correctly sized creative
and a deliberately oversized one — 49 tracked elements moved **0px** and no viewport
gained a horizontal scrollbar.

The sidebar slot is one DOM node repositioned by CSS grid, never two nodes with one
hidden, so no ad is ever requested twice.

## Principles

- One accent colour. If something needs emphasis and is not a link, pill or active
  state, use weight or space instead.
- No animation beyond default focus and hover colour changes. No transitions on
  layout properties.
- `prefers-reduced-motion` disables smooth scrolling and collapses all durations.
- Semantic HTML first: one `<h1>` per page, no skipped heading levels, real
  `<article>`, `<nav>`, `<time>` and `<figure>`.
- Focus is always visible: 2px accent outline at 3px offset, never removed.
- Wide content (tables, code) scrolls inside its own container. The page body never
  scrolls horizontally.

## Motion

CSS only. No animation library, no parallax, no carousels, and no measurable JS weight.

### Scroll reveal

`.reveal` uses native scroll-driven animation:

```css
@media (prefers-reduced-motion: no-preference) {
  @supports (animation-timeline: view()) {
    .reveal {
      animation-name: reveal-rise;
      animation-timing-function: linear;
      animation-fill-mode: both;
      animation-timeline: view();
      animation-range: entry 0% entry 42%;
    }
  }
}
```

Two details that are load-bearing:

- **Longhands, not the `animation` shorthand.** The shorthand resets
  `animation-duration` to `0s`, which silently kills a scroll-driven animation — it
  completes instantly and reveals nothing. Omitting duration leaves it `auto`, which is
  what a `view()` timeline needs. This was caught by measuring, not by reading.
- **The hidden state lives entirely inside the `@supports` block.** Scroll-driven
  animation is the only thing that can reveal an element, so a browser that cannot run
  it must never have hidden the element. Verified three ways: with support (below-fold
  elements correctly start hidden), with the `@supports` condition forced false (nothing
  hidden), and under reduced motion (nothing hidden).

### Page transitions

`@view-transition { navigation: auto }` — the CSS cross-document route, chosen over
Astro's `ClientRouter` because it costs **zero JavaScript**. Chromium animates it today;
elsewhere navigation is unanimated, which is the correct fallback.

### Hover and focus

160–180ms `ease` on colour, background, border and text-decoration for links, buttons,
pills and tags; a 3% scale on card images over 420ms. Nothing animates layout
properties.

### Reduced motion

`prefers-reduced-motion: reduce` sets `animation: none`, `opacity: 1` and
`transform: none` on all reveals, and neutralises the view-transition pseudo-elements.

### Measured cost

Lighthouse after adding motion: **100 performance, 100 accessibility, 100
best-practices, 100 SEO** on both the landing page and a post page, with CLS 0 and TBT
0 ms.
